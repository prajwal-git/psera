# Build and installation

## Android

Install Flutter 3.47.5, JDK 17 with `javac`, Android SDK platform 36, build-tools 36.0.0 and NDK 28.2.13676358. Run `flutter doctor`, then `flutter doctor --android-licenses`. Android Studio can install these packages.

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
flutter build apk --release
flutter build appbundle --release
```

Outputs:
- Debug: `build/app/outputs/flutter-apk/app-debug.apk`
- Release-mode APK: `build/app/outputs/flutter-apk/app-release.apk`
- AAB: `build/app/outputs/bundle/release/app-release.aab`

The app ID is `com.psera.shop`. Verify ownership/availability and choose your final ID before creating production Firebase or store registrations. Minimum Android version is API 24 (Android 7.0). An AAB is for Play distribution and cannot be installed by tapping it like an APK.

For a device connected with USB debugging, use `adb install -r PSERA-demo.apk`. Otherwise copy/download the APK to the phone and tap it. On Android, permission to install an APK is granted per source app in device settings. Managed devices may prohibit sideloading.

### Store signing

Generate and privately back up an upload keystore using `keytool` or Android Studio. Create `android/key.properties`:

```properties
storePassword=YOUR_LOCAL_PASSWORD
keyPassword=YOUR_LOCAL_PASSWORD
keyAlias=upload
storeFile=/absolute/path/to/upload-keystore.jks
```

The Gradle file automatically uses it for release builds. Never share the keystore/passwords in chat, commit them, or include them in a distributable source ZIP. Without this file, release-mode builds use a development certificate. The provided demo APK/AAB use a development certificate.

For Google Play, first complete the live backend, policies, support information, privacy/data-safety declarations, product content, device testing and store listing. Upload a properly signed AAB to an internal test track, verify on actual devices and then submit it for review. No store publication is performed here.

## iPhone/iPad

A signed Apple build requires macOS and Xcode. The included `ios/` project is generated by Flutter; it has not been compiled in this Linux workspace.

On a Mac:

```sh
flutter pub get
flutter doctor
open ios/Runner.xcworkspace
```

In Xcode, select **Runner → Signing & Capabilities**, choose your Apple development team, verify the bundle ID `com.psera.shop`, and configure automatic signing/provisioning. Select a connected iPhone or simulator and run. Install CocoaPods if your chosen Flutter plugin toolchain needs it.

For distribution with an enrolled Apple Developer account:

```sh
flutter build ipa --release
```

Review signing/export options in Xcode Organizer and distribute through TestFlight/App Store Connect. The usual installation path for testers is TestFlight, not an unsigned IPA or APK. Apple development provisioning has different device/account limits. No Apple credentials are bundled and no IPA is fabricated.

## Optional browser build

The same source has a Flutter web target for inspection; the mobile app is not a WebView wrapper.

```sh
flutter build web --release --no-web-resources-cdn
python3 -m http.server 8080 --directory build/web
```

Visit `http://localhost:8080`. Use an HTTP server, not `file://`. Browser storage permissions are required for demo persistence.
